# オーディオブートローダ

PAUSE ジャックに音声（WAV）を流し込んで、アプリ（`gate_sequencer.bin`）を書き換える仕組みです。
WCH-LinkE なしでファームを更新できます。
ブートローダ自体は、出荷時に WCH-LinkE で書き込んでいます。

ユーザー向けの更新手順は、製品のマニュアルの「ファームウェアのアップデート」にあります。

## 仕組み

### Flash の配置

| 領域 | アドレス | 大きさ | 内容 |
|---|---|---|---|
| ブートローダ | 0x1FFFF000（ブート領域） | 1920B | `bootloader/bootloader.bin`。音声の更新では書き換えない |
| アプリ | 0x08000000〜0x08003FBF | 16320B | `gate_sequencer.bin`。リンカで最後のページを使わないようにしている |
| メタデータ | 0x08003FC0 | 64B | 検証済みのアプリの情報（下記） |

メタデータは、更新の最後に受けた END パケットの先頭 64B をそのまま書いたものです。

| オフセット | 内容 |
|---|---|
| 0 | 3（END パケットの種別）。有効の印。消去後の 0xFF なら無効 |
| 1〜2 | 製品 ID（0x4753） |
| 3〜4 | バージョン |
| 5〜6 | アプリのバイト数 |
| 7〜10 | アプリの CRC32 |
| 11〜63 | 0 |

### 起動の流れ

1. オプションバイトの設定で、電源投入時はブート領域から起動する
2. ブートローダが 165 を読む。Push A と Push B が両方押されていれば、書き込みモードに入る
3. 押されていなければメタデータを確かめる。有効の印・製品 ID・長さ・アプリの CRC32 がすべて合えば、起動先をユーザー領域にしてソフトウェアリセットし、アプリを起動する
4. 合わなければ（アプリが無い・壊れている）、操作なしで書き込みモードに入る

### 書き込みモード

- PAUSE 入力（PA1）をポーリングし、立ち上がり（ジャック側）の時刻から復調する（`bootloader/abl_demod.c`）
- 復調したビット列をパケットにし（`abl_packet.c`）、受信ページ管理の指示に従って Flash を書く
  - START: 新しい更新ならメタデータページを消す。途中で止まっても、次の起動で書き込みモードに戻る
  - DATA: まだ書いていないページだけ書く（2 周目は 1 周目で取れなかったページを拾う）
  - END: 全ページそろっていれば、アプリ全体の CRC32 を確かめる。合えばメタデータを書いてアプリを起動する
- 表示

| 状態 | 表示 |
|---|---|
| 書き込み待ち（まだ 1 ページも書いていない） | ステップ LED 1 が約 0.7 秒ごとに点滅 |
| 信号にロックしている | PAUSE LED（LED_E）が点灯 |
| 受信中 | ステップ LED が進捗バー（16 段） |
| エラー（別製品の WAV、ページの欠け、CRC32 不一致） | 全 LED が約 3 秒点滅。受信は続ける |
| 完了 | 全ステップ LED が約 2 秒点灯し、アプリを起動 |

### 大きさの工夫（1920B に収めるため）

ブート領域は 1920B しかありません。現在 1876B です（`make` で表示されます）。

- 割り込みを使わず、`FUNCONF_TINYVECTOR` でベクタテーブルを省く
- PLL を使わず HSI 24MHz で動かす（Flash の待ちが 0 になるので、CRC32 の計算は 48MHz とほぼ同じ速さ）
- printf を使わない
- パケットを固定長にし、CRC は CRC32 の 1 種類にする。メタデータは END パケットをそのまま書く
- GPIO の設定は `funPinMode` を使わず、レジスタに一度に書く

## 音声の形式

| 項目 | 値 |
|---|---|
| 変調 | 正弦波 2 値 FSK。1 ビット = 1 周期。0 = 6kHz、1 = 3kHz |
| WAV | 48kHz・16bit・ステレオ（左右同じ信号）・振幅 0.99（フルスケール比） |
| バイト | LSB から送る。多バイトの値はリトルエンディアン |
| パケット | プリアンブル（0 を 48 ビット）+ 同期語 0x2DD4 + 種別（1B）+ 本体（65B）+ CRC32（4B）+ ポストアンブル（0 を 4 ビット） |
| 種別 | 1 = START、2 = DATA、3 = END |
| START / END の本体 | 製品 ID（2B）、バージョン（2B）、アプリのバイト数（2B）、アプリの CRC32（4B）、0 埋め |
| DATA の本体 | ページ番号（1B）+ 64B（最後のページの余りは 0xFF） |
| 並び | [START、DATA x ページ数] を 2 周 → END |
| パケットの間 | 20ms の無音。ブートローダが Flash を書く間は CPU が止まり、音を拾えないため |
| CRC32 | IEEE（Python の `zlib.crc32` と同じ） |

- 復調は、パケットごとにプリアンブルで短い周期を測ってロックする。短い周期と長い周期をそれぞれ追従させ、その中間で 0 / 1 を判定する
- 1 ビットの長さは「次の周期の立ち上がり」で決まる。そのため、パケットの最後のビットを確定させるポストアンブルが要る
- 7KB のアプリで約 39 秒

## ビルド

```bash
make            # アプリとブートローダ（サイズを表示）
make release    # WCH-LinkE 用イメージと更新用 WAV
```

| ファイル | 内容 |
|---|---|
| `bootloader/bootloader.bin` | ブートローダ（ブート領域に書く） |
| `gate_sequencer.bin` | アプリ |
| `gate_sequencer_factory.bin` | WCH-LinkE 用イメージ（アプリ + 0xFF 埋め + メタデータ、16KB） |
| `gate_sequencer_update.wav` | 更新用 WAV |

- バージョンは `make release FW_VERSION=2` のように指定します（既定は 1）

## WCH-LinkE での書き込み

ブートローダは、出荷時に書き込み済みです。書き直すとき、または新しいマイコンに書くときの手順です。
WCH-LinkE とモジュールのヘッダ J25 を、GND（1 番）と SWIO（2 番）でつなぎ、モジュールの電源を入れておきます。

Linux で WCH-LinkE を USB から直接使える場合:

```bash
make flash              # アプリとメタデータ（gate_sequencer_factory.bin）
make flash_bootloader   # ブートローダとオプションバイト
```

Windows（`minichlink.exe`）の場合:

```powershell
.\minichlink.exe -w gate_sequencer_factory.bin flash
.\minichlink.exe -a -U -w bootloader.bin bootloader -b
.\minichlink.exe -w +a55a37c8 option
.\minichlink.exe -r + option 16
```

1. 1 行目でアプリとメタデータを書く
2. 2 行目でブートローダをブート領域に書く（`-U` はブート領域の書き込み許可）
3. 3 行目で、オプションバイトを書く（RDPR = 0xA5 読み出し保護なし、USER = 0x37、nUSER = 0xC8）
   - USER = 0x37 は、bit5（START_MODE）= 1 で電源投入時にブート領域から起動、bit4..3（RST_MODE）= 10 で PD7 を NRST にする設定
   - minichlink は 64B を読んで指定の 4 バイトだけ差し替えて書くので、データバイトと書き込み保護は変わらない
4. 4 行目で読み戻し、先頭が `a5 5a 37 c8` になっていることを確かめる
5. 電源を入れ直し、アプリが動くことを確かめる

## 動作の補足

- 書き込みモードに入れるのは電源投入時だけ。アプリ動作中にリセットボタンを押しても、書き込みモードには入らない
- アプリ動作中のリセットボタン（NRST）では、ブート領域を通らずアプリが再起動する
- 64B ページの消去と書き込みは、それぞれ約 3ms かかる。パケットの間の無音 20ms はこのためにある
